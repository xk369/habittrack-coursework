# План развертывания

## Статус

Подготовлен предварительный план развертывания на уровне требований к
инженерной упаковке. Конкретная облачная платформа, домен, способ публикации и
production-настройки будут уточнены позже на deploy-этапе.

## 1. Цель развертывания

HabitTrack должен быть пригоден для:

- локального воспроизводимого запуска во время разработки и проверки;
- демонстрации проекта на защите;
- облачного развертывания как полноценного клиент-серверного приложения;
- фиксации доказательной базы для отчета и презентации: README, команды
  запуска, скриншоты, ссылка на deploy и результаты проверки.

## 2. Контейнеризированный запуск

Проект должен поддерживать контейнеризированный запуск.

На следующих этапах необходимо подготовить:

- Dockerfile для серверной части;
- Dockerfile или эквивалентную сборочную схему для клиентской части, если это
  потребуется выбранным способом deploy;
- docker-compose для локального запуска приложения вместе с зависимыми
  сервисами;
- README с понятной инструкцией запуска.

Контейнеризация нужна для воспроизводимости окружения и выполнения требований
курсовой работы по Docker/README/deploy.

## 3. Конфигурация через окружение

Серверная конфигурация должна выноситься из исходного кода в окружение.

На следующих этапах необходимо предусмотреть:

- `.env.example` со списком необходимых переменных;
- отдельные значения для локального запуска и облачного deploy;
- отсутствие секретов в репозитории;
- возможность менять параметры подключения, режим работы и другие настройки
  без изменения исходного кода.

Это поддерживает связь с методологией двенадцати факторов, особенно с
принципом конфигурации через окружение.

## 4. Подключение базы данных

PostgreSQL должен подключаться как отдельный сервис, а не как встроенное
локальное хранилище приложения.

Для локального запуска база данных может подниматься через docker-compose. Для
облачного deploy база данных может быть вынесена во внешний управляемый сервис
или отдельный контейнер, в зависимости от выбранной платформы.

Конкретные параметры подключения, имя базы, пользователь и пароль должны
передаваться через переменные окружения.

## 5. Готовность к облачному deploy

Конкретная облачная платформа пока не фиксируется. На deploy-этапе необходимо
выбрать вариант, который позволит:

- разместить backend;
- разместить frontend;
- подключить PostgreSQL;
- передать переменные окружения;
- проверить регистрацию, вход, пользовательские сценарии, административные
  сценарии и блокировку пользователя;
- получить публичную ссылку для отчета и защиты.

Стек должен быть готов к такому deploy за счет контейнеризации, конфигурации
через окружение и отделения приложения от данных.

## 6. Что пока не фиксируется

На текущем этапе не фиксируются:

- конкретная облачная платформа;
- домен и HTTPS-настройки;
- production-сервер;
- CI/CD;
- мониторинг и логирование;
- конкретная схема сети и proxy;
- финальная схема хранения статических файлов.

Эти решения принимаются после проектирования модели данных, API, реализации и
первичной проверки локального запуска.
